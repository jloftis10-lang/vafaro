## What this is

OwnerGauge is an M&A education and lead-generation site with a business valuation
and Deal Readiness assessment. It includes authority pages, industry guides,
resources, deterministic risk/readiness logic, and an emailed report. There is
no CMS, auth, dashboard, AI-generated content, or admin panel.

## Commands

```bash
npm install
cp .env.example .env.local   # fill in Supabase + Resend credentials
npm run dev                  # dev server
```

## Architecture

**Stack**: Next.js App Router + TypeScript, Tailwind CSS v4, Supabase
(Postgres) for storage, Resend for email, deployed on Vercel.

**Request flow**: `/calculator` renders the five-step `AssessmentForm`. The
browser calculates valuation, readiness, risks, strengths, recommendations,
and the adaptive CTA deterministically. `AssessmentEmailCaptureForm` POSTs
the answers and email to `src/app/api/assessment/submit/route.ts`. The route
re-validates with Zod, recomputes every result server-side, inserts into
Supabase, and sends the report through Resend.
A failed Supabase insert fails the request (500); a failed Resend send does
not — the submission is already saved, so email errors are only logged
(see the comment in `route.ts` about the Resend SDK returning `{ error }`
rather than throwing).

**Valuation math and data concerns are separated**:
- `src/lib/valuation.ts` — `calculateValuation()` is the *only* place the
  math happens: `selectBenchmarks()` (`src/lib/data/valuation-benchmarks.ts`)
  picks the applicable market benchmark(s) for the industry+metric →
  `computeQualityPosition()` (`src/lib/valuation/quality-position.ts`)
  positions the company within that benchmark's low-high multiple range,
  rather than shifting a fixed midpoint by additive adjustments → the
  positioned multiple is widened into a display range (± 0.4x, clamped to
  `[benchmark low − 0.5, benchmark high + 0.5]`) → final range is
  `SDE/EBITDA × (positioned multiple range)`. Pure function, no I/O, safe to
  call from client or server. It also generates templated (non-AI) prose
  explaining where the business fell within the range and why — see
  `docs/valuation-benchmark-policy.md` for the full benchmark-selection
  policy this depends on.
- `src/lib/data/industries.ts` — grouped product taxonomy only; it does not
  contain multiples, content, or lead-fit scores.
- `src/lib/data/valuation-assumptions.ts` — the per-industry and generic
  SDE/EBITDA multiple ranges, each Evidence Quality E ("OwnerGauge inference" —
  directional research, not a cited institutional dataset). Consumed by
  `valuation-benchmarks.ts`, which wraps them into `ValuationBenchmark`
  records rather than being read directly by `valuation.ts`.
- `src/lib/data/adjustments.ts` — the four company-quality factor tables
  (trend, owner involvement, customer concentration, recurring revenue),
  consumed by `quality-position.ts` to position a company within its
  benchmark's range rather than as additive point deltas.
- `src/lib/data/form-options.ts` — UI labels for those same option keys,
  kept separate so copy edits can't accidentally touch the math.
- `src/lib/types.ts` — the shared option/type vocabulary
  (`TrendOption`, `OwnerInvolvementOption`, etc.) that ties the form, the
  adjustment tables, the API schema, and the DB columns together. When
  adding a new qualitative input, this is the type to extend first.

**Server-only boundaries**: `src/lib/supabase-server.ts` and
`src/lib/resend.ts` read `SUPABASE_SERVICE_ROLE_KEY` / `RESEND_API_KEY` from
`process.env` and must never be imported into a Client Component — the
service role key bypasses Row Level Security and must not reach the browser.
Env vars that are safe for the client are prefixed `NEXT_PUBLIC_`; the two
above deliberately are not (see `.env.example`).

**Database**: `0001_create_submissions.sql` is legacy;
`0002_create_assessment_submissions.sql` defines the current table. RLS is
enabled with no policies; the server-side API writes with the service role.

**Path alias**: `@/*` maps to `src/*` (see `tsconfig.json`).
